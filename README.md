# תשיעיות — התפקידים במגרש

אפליקציית PWA בעברית: חוברת לכל תפקיד במגרש, לילדים שמשחקים תשיעיות.
עובדת אופליין במלואה — פונטים, אייקונים ודיאגרמות מקומיים, בלי תלות ברשת אחרי הטעינה הראשונה.

## מבנה

```
index.html              שני המסכים: ספרייה וחוברת (בלי תוכן)
css/app.css             העיצוב
js/pitch.js             ציור המגרש והרצת התנועה — משותף לתצוגה, לתמונות מוקטנות ולעריכה
js/library.js           מסך הבית: כרטיס לכל חוברת
js/booklet.js           מסך חוברת: מגרש, צ'יפים, פאנל, ניווט
js/quiz.js              מבדק: שאלות נגזרות מהתרחישים
js/terms.js             מילון המונחים: סימון מונח בטקסט ופתיחת הסבר
js/store.js             התקדמות ותוצאות על המכשיר
js/app.js               טעינה וניתוב
editor.html             העורך — לא מקושר מהאפליקציה
css/editor.css js/editor.js
content/booklets.json   מסך הבית, מילון המונחים ורשימת החוברות
content/formations.json מערכים ומיקומי ברירת מחדל לפי מספר חולצה
content/kesher-6.json   חוברת מספר 6
content/kesher-8.json   חוברת מספר 8
content/left-back.json  חוברת מגן שמאלי
content/winger.json     חוברת כנף
fonts.css fonts/ manifest.webmanifest sw.js
icons/logo.svg          מקור הלוגו — מעגל האמצע וקו האמצע; שאר האייקונים נגזרים ממנו
```

## כתובות

| כתובת | מסך |
|---|---|
| `#/` | ספרייה |
| `#/b/kesher-8` | חוברת מתחילתה |
| `#/b/kesher-8/high-press` | תרחיש מסוים — זה הקישור לשלוח בוואטסאפ |
| `#/t/kesher-8` | האימון של היום — שלושה תרחישים נבחרים |
| `#/q/kesher-8` | מבדק על כל החוברת |
| `#/q/kesher-8/high-press` | מבדק על תרחיש אחד |
| `#/x/<מקודד>` | תרחיש בודד שנשלח מהעורך, בלי לפרסם אותו |

מעבר בין תרחישים מעדכן את הכתובת בלי להוסיף צעד להיסטוריה, כך ש"אחורה" חוזר לספרייה
ולא מדלג תרחיש אחורה בכל לחיצה. `?b=<id>` מהגרסה הקודמת עדיין נתמך.

## הרצה מקומית

הקבצים נטענים ב-`fetch` וב-ES modules, ולכן פתיחה ישירה של `index.html` מהדיסק לא תעבוד.
צריך שרת מקומי:

```bash
python3 -m http.server 8000
# ואז http://localhost:8000
```

## הוספת תוכן

**תרחיש** נוסף למערך `scenarios` בתוך קובץ החוברת. שדות:

| שדה | משמעות |
|---|---|
| `id` | מזהה קבוע וייחודי בחוברת. ההתקדמות של הילד נשמרת לפיו — **לא לשנות אחרי פרסום** |
| `phase` | שלב המשחק: `החזקה` · `הגנה` · `מעברים` · `עם הכדור` (קובע את צבע הנקודה בצ'יפ; שלב חדש צריך שורה ב-`css/app.css`) |
| `chip` / `title` / `sub` | כותרת קצרה לצ'יפ, כותרת מלאה, ותת-כותרת |
| `pos` | מיקומי שחקנים לפי מספר חולצה. מי שלא מופיע — במיקום ברירת המחדל מ-`formations.json` |
| `ball` | מיקום הכדור |
| `ghosts` | נקודות התחלה של תנועה (עיגול מקווקו) |
| `arrows` | `run` ריצה · `pass` מסירה · `opt` אפשרות · `press` תנועת יריב. `bend` מכופף לקשת |
| `zones` / `shadow` | הדגשת אזור או צל כיסוי |
| `does` / `mistake` / `cue` | הטקסט בפאנל. `cue` מוצג ראשון — זה מה שנשאר בראש אחרי שבוע — ו-`mistake` נפתח בנגיעה |

`drills` ו-`tests` בחוברת **אינם מוצגים** — תרגילים ומדדים הם תוכן להורה,
ואזור "איך מאמנים את זה בפועל" ירד מהמסך כי הוא חזר תחת כל תרחיש. הטקסט
נשאר בקבצים ולא נמחק, וממתין להחלטה איפה מקומו.

מערכת הצירים היא `viewBox="0 0 400 620"` — השער שלנו למטה, מתקיפים כלפי מעלה.

**מונח** למילון נוסף ל-`terms` ב-`content/booklets.json`: `"מונח": "שורת הסבר אחת"`.
ההופעה הראשונה של המונח בכל תרחיש — בכותרת, בתת-כותרת, ב-`does` או ב-`mistake` —
הופכת לכפתור שפותח את ההסבר מתחת לפסקה. הצ'יפים נשארים נקיים, כי כפתור בתוך
כפתור אינו חוקי ושובר את הניווט. תחיליות (ה, ב, ל, מ, ו, ש, כ) נתפסות מעצמן,
כך ש"בחצי-מרחב" מסומן יחד עם הבי"ת. **מונח אסור שיכיל "ימין" או "שמאל"**:
הטקסט מגיע למילון אחרי `mirrorText`, ומונח שמתהפך לא היה נמצא בצד אחד מהשניים.

**חוברת** חדשה: קובץ JSON ב-`content/`, ורישום `{id, file}` שלו ב-`content/booklets.json`.
הכותרת, הפתיח והתרחישים נקראים מהקובץ עצמו, כדי שלא יהיו שני מקומות שצריך לעדכן.
`booklets.json` מחזיק גם את טקסטים של מסך הבית (`home`), ואת `legacyBooklet` —
החוברת שאליה שייכים הסימונים מהגרסה שקדמה למסך החוברות.

`role` בחוברת קובע איזה שחקן מודגש בוורוד — הדיאגרמות מתארות תפקיד מסוים,
ולכן ההדגשה נגזרת מהחוברת ולא מהגדרה גלובלית. `titleB` הוא השם כשהמגרש
משוקף, ו-`side` מחזיק את תוויות המתג (`label`, `a`, `b`, `hintA`, `hintB`).

## הצד של השחקן

מתג מעל המגרש הופך את כל התרחישים לצד השני, לילד שרגלו החזקה שמאל.
הבחירה נשמרת ב-`k8:side` וחלה על מסך החוברת, על התמונות המוקטנות בספרייה
ועל המבדק.

השיקוף מיושם על **הנתונים** (`mirrorScenario` ב-`pitch.js`) ולא על הציור.
זו הנקודה החשובה: כך גם התשובות במבדק מגיעות משוקפות יחד עם הלוח, בלי
להמיר קואורדינטות בזמן הבדיקה — מסירה שהלכה למספר 11 הולכת למספר 7,
והמרחק במטרים נשאר נכון.

מספר חולצה שומר על הצד המקובל שלו: הבבואה מחליפה בין 2 ל-5 ובין 7 ל-11,
כך שמה שמתהפך הוא האסימטריה של התרחיש ולא סידור הקבוצה. הזוגות **נגזרים
מהמערך עצמו** — שני מספרים שמיקום ברירת המחדל שלהם הוא בבואה זה של זה —
ולכן מערך חדש לא דורש רשימה חדשה בקוד.

בתפקיד אגף השיקוף מחליף גם את הזהות: מגן שמאלי הופך למגן ימני, המספר
המודגש עובר מ-5 ל-2, והכותרת ל-`titleB`. בתפקיד מרכזי כמו ה-8 המספר
נשאר, ומתהפך רק הצד שבו הוא פועל.

העורך תמיד עובד בכיוון המקורי, כי הוא עורך את המקור.

## הרצת התנועה

כפתור **"הראה לי את התנועה"** מתחת למגרש מריץ את התרחיש פעם אחת: השחקנים
זזים לאורך חצי הריצה, הכדור נוסע לאורך חץ המסירה, והיריב לאורך חץ הלחץ.
בסוף חוזרת התמונה המלאה עם החיצים.

**אין כאן תוכן חדש.** החץ כבר מחזיק מסלול מלא (`a`, `b`, `bend`), ו-`plan`
ב-`pitch.js` רק מחליט מי הולך לאורכו ומתי. **תרחיש שתוסיף יקבל הרצה לבד.**

**מי זז.** מי שמצויר בסוף החץ — מוסכמת השרטוט הרווחת, שבה השחקן כבר הגיע
ונקודת ההתחלה מסומנת בעיגול מקווקו. אם אין שם אף אחד, מי שמצויר בתחילתו.
ואם אין גם שם, מי שמצויר **על** החץ — הוא באמצע הדרך, ואז הוא עוצר במקום
שבו הוא מצויר ושארית החץ היא לאן שהוא ממשיך.

**הקושי אינו בציור אלא בתזמון.** שרטוט אחד מחזיק כמה אירועים שקרו זה אחר
זה, והחיצים אינם אומרים מי קדם למי. הסדר נגזר מהגיאומטריה:

| מה שרואים בשרטוט | מה שנגזר |
|---|---|
| מסירה שמתחילה במקום שאליו הגיעה מסירה קודמת | שרשרת — השנייה מחכה לראשונה |
| ריצה שמסתיימת בנקודת יציאה של מסירה | הוא המוסר, ומגיע לשם לפניה |
| מסירה שיוצאת מהמקום שבו עומד מי שרץ | מסר ואז יצא לריצה — הקיר עם החלוץ |
| ריצה שמסתיימת ביעד של מסירה | מתוזמן להגיע **יחד** עם הכדור, ואם הריצה ארוכה מהמסירה — המסירה ממתינה לו |
| מסירה שנוחתת במקום שבו מתחילה ריצה | קיבל, ואז ממשיך עם הכדור |
| הכדור מצויר לרגלי מי שזז | הובלה — הכדור נוסע איתו |
| יריב שעומד על הכדור | הכדור שלו, ואף אחד משלנו לא מוביל אותו |

**הכדור מקבל נהג אחד בכל רגע** — המהלך האחרון שכבר התחיל. בלי זה גם ההובלה
וגם המסירה כותבות לו מיקום בכל פריים, והאחרונה ברשימה מנצחת את האחרונה בזמן.

**משך התנועה נגזר מהמרחק** — צעד קצר וספרינט של שלושים מטר אינם אורכים אותו
זמן, והכדור מהיר מהרגליים.

**התמונה בסוף ההרצה נגזרת מהמקום שבו כל אחד באמת עצר**, ולא מהנתונים: השרטוט
הוא לפעמים הרגע *שלפני* הפעולה — הכדור מצויר לרגלי המוסר, או השחקן בתחילת
חץ הריצה — וציור התרחיש כמות שהוא היה מחזיר אותם אחורה בקפיצה.

**מה לא זז:** חץ `opt` הוא אפשרות שלא נבחרה. חץ ריצה שנקודת התחלה מסומנת
ב**שני** קצותיו אינו תנועה אלא טווח — כך מצוירת מפת התפקיד, ולכן היא היחידה
שאינה מקבלת כפתור.

בתנועה מופחתת הכפתור מדלג ישר לתמונה המלאה.

## האימון של היום

מבדק של שלוש-עשרה שאלות הוא יותר מדי לילד בערב אחרי אימון, ומבחן שנעשה פעם
אחת אינו מלמד. `#/t/<חוברת>` נותן **שלושה תרחישים**, ו-`dailyPicks` ב-`store.js`
בוחר אותם לפי מה שנשמר: קודם מה שפוספס בפעם האחרונה, אחר כך מה שעוד לא נוסה,
ולבסוף מה שהצליח ולא נגעו בו הכי הרבה זמן. זו חזרה מרווחת על הנתונים שכבר היו —
`saveQuizResult` רק הוסיף חותמת `at`.

הבחירה נעשית בכל כניסה מחדש ולכן אינה בכתובת. המבדק המלא נשאר במקומו, כמהלך
של סוף חוברת.

## המבדק

**השאלות נגזרות מהתרחישים ולא נכתבות בנפרד**, בשני אופנים:

**"לאן אתה זז?"** — כשהשחקן בלי כדור. חץ הריצה שלו הוא בדיוק "מאיפה לאן":
תחילתו היא המצב שלפני הפעולה, וסופו התשובה. נדרש חץ ריצה שמסתיים במיקומו
הסופי ואורכו לפחות 30 יחידות.

**"לאן אתה מוסר?"** — כשהכדור אצלו. החץ שיוצא ממנו הוא ההחלטה. הציון לפי
**מי קיבל**, לא לפי מטרים: נגיעה בשחקן הנכון היא תשובה נכונה. השחקן ממוקם
במקום שממנו יוצא החץ — בקיר עם החלוץ, למשל, הוא מוסר מנקודת ההתחלה ורק
אחר כך רץ קדימה.

**שתי מוסכמות שרטוט לריצה** נתמכות: חץ שמסתיים במקום שבו השחקן מצויר
(הוא כבר הגיע, והשאלה היא לאן), וחץ שיוצא ממנו אל היעד (הוא עוד בדרך).
בראשונה התשובה היא מיקומו המצויר, בשנייה סוף החץ.

השאלה נבחרת לבד: חץ מסירה שיוצא ממנו גובר על הריצה, וחץ אפשרות גובר רק
כשאין לו ריצה **אל מקומו** — ריצה שיוצאת ממנו היא מה שהוא עושה אחרי
המסירה ולכן אינה גוברת עליה. **תרחיש בלי יריבים אינו נכנס למבדק**: הוא
מפה ולא סיטואציה, וכך "מפת התפקיד" נופלת מעצמה בכל חוברת.
**תרחיש שתוסיף ייכנס למבדק לבד.**

הילד רואה את המגרש בלי חיצים, נקודות התחלה, אזורים וצל, ומעליו שורת הקשר
שנגזרת מהמגרש עצמו: שלב המשחק ומי מחזיק בכדור. ההקשר מחושב על **הרגע
שנשאל** ולא על התרחיש המלא — כדי שכדור שצויר בסוף הפעולה לא ייראה כאילו
אינו אצל אף אחד. מאותה סיבה, כשהכדור צויר לרגלי השחקן בסוף התנועה, הוא
מוחזר אליו לנקודת ההתחלה.

**המשוב במטרים.** 8 יחידות ציור הן מטר אחד — נבדק מול רחבת העונשין בשרטוט,
208 על 91 יחידות שהם 26 על 11.4 מטר. עד 3 מטר מדויק, עד 6 קרוב. פספוס גדול
נותן ניסיון שני **לפני** שהתשובה מתגלה. אחרי הגילוי מופיע חץ הריצה האמיתי
לצד הסימון שלו, ואז שאלה שנייה: איזה מבין שלושה משפטי `cue` מהחוברת מתאים
לתרחיש.

**תרחיש שהוא החלטה ולא תנועה** יכול לשאת שדה `quiz` משלו:

```jsonc
"quiz": {
  "type": "choice",
  "ask": "איבדת את הכדור. אתה הכי קרוב אליו. מה עכשיו?",
  "options": ["...", "...", "..."],
  "answer": 0,
  "why": "עד חמישה מטר — לוחץ."
}
```

התוצאות נשמרות לפי מזהה תרחיש ב-`k8:quiz`, והסיכום מציע לחזור רק על מה שפוספס.
הכניסה למבדק היא כפתור על כרטיס החוברת בספרייה, והוא מציג גם את התוצאה
האחרונה. `#/q/<חוברת>` עדיין עובד ישירות.

## המספר של הילד

שאלה אחת בפתיחה הראשונה — "איזה מספר אתה?" — ואחריה החוברת של התפקיד שלו
עולה ראשונה בספרייה ומסומנת. המספרים מוצעים לפי `order` של המערכים, כך שמערך
חדש לא דורש רשימה בקוד. הבחירה נשמרת ב-`k8:me`, ויש לה שלושה מצבים: לא נשאל
עדיין · מספר · 0 אם בחר לדלג. בלי המצב השלישי השאלה הייתה חוזרת בכל פתיחה.

בשיקוף ההשוואה היא מול התפקיד המשוקף, כך שילד שמאלי שהוא מספר 2 מקבל את
חוברת המגן שהופכת עבורו ל-2.

## העורך

`editor.html` — לא מקושר משום מקום באפליקציה, כדי שהילד לא ייתקל בו. פותחים בסימנייה.
אותו מודול ציור ואותו עיצוב, כך שמה שמסודר שם נראה בדיוק כמו אצל הילד.

**כלים.** ברירת המחדל היא בחירה: גוררים שחקנים, כדור, יריבים וקצוות של חיצים.
לחיצה על חץ או אזור בוחרת אותו, ואז מופיעות הידיות שלו ופאנל לשינוי סוג ותווית.
`נקודת התחלה` הוא הקיצור המרכזי — לוחצים על שחקן וגוררים, ונופלת נקודת התחלה
במקום הישן עם חץ ריצה אליו. שאר הכלים: ארבעה סוגי חיצים, יריב, אזור, צל כיסוי ומחיקה.

הידיות מוצגות רק במצב בחירה ורק לפריט הנבחר — אחרת הן יושבות מעל השחקנים
ותופסות את הגרירה במקומם. הזיהוי בלחיצה נעשה לפי קרבה ולא לפי מי מצויר מעל מי.

**טיוטות.** כל שינוי נשמר אוטומטית ב-localStorage ולא מתפרסם. הכפתור בראש הדף
זורק את הטיוטה וחוזר לגרסה שב-`content/`.

**ייצוא.** `הורד את החוברת` נותן קובץ JSON שנכנס ל-`content/` במקום הקיים —
זה מה שמפרסם. `העתק קישור לשיתוף` מקודד תרחיש בודד בתוך הכתובת עצמה,
כך שאפשר לשלוח אותו בלי לפרסם כלום.

**ייבוא.** מדביקים דף HTML שהוכן קודם (או רק את מערך `S`), והעורך שולף ממנו
את התרחישים ומציג אותם עם תצוגה מוקטנת לפני ההוספה. ההערכה מיועדת לקבצים
שאתה יצרת — לא להדביק לשם קוד ממקור לא מוכר.

## מטמון וגרסאות

- **תוכן** (`content/*.json`) נשלף מהרשת קודם, עם נפילה למטמון אחרי 2.5 שניות.
  תרחיש חדש מופיע כבר בפתיחה הראשונה, ואין צורך לגעת ב-`sw.js`.
- **קוד** (HTML/CSS/JS) נשמר cache-first מתוך מטמון שנושא מספר גרסה — כדי שכל
  הקבצים שנטענים יהיו מאותה גרסה. אחרי שינוי קוד **חובה** להעלות את `VERSION`
  ב-`sw.js` (`v5` → `v6`), אחרת המכשיר ימשיך להגיש את הקוד הישן.
- כשגרסה חדשה משתלטת, הדף מרענן את עצמו פעם אחת (`controllerchange` ב-`app.js`),
  כך שהעדכון נראה בפתיחה הבאה בלי רענון ידני.
- מספר הגרסה שמוצג בתחתית מסך הבית מגיע מ-`version` ב-`booklets.json` —
  שווה להעלות אותו בכל פרסום, כדי לדעת במבט אם העדכון הגיע למכשיר.
